# 动画

图表动画分两个阶段，它们用不同的机制实现 —— 这一点决定了动效是否「自然」。

| 阶段     | 触发时机     | 机制                                            |
| -------- | ------------ | ----------------------------------------------- |
| **入场** | 组件首次挂载 | 推进 `progress`，每个图元按各自延迟从基线生长   |
| **更新** | 数据变化     | 在「当前显示值 → 新值」之间插值，**不重播入场** |

## 配置

`animation` 接受 `boolean` 或配置对象：

```tsx | pure
<LineChart
  animation={{
    duration: 620, // 毫秒
    easing: 'easeOutQuint',
    stagger: 0.35, // 0~1，最后一个图元晚多少比例开始
    delay: 0, // 整体延迟
  }}
/>
```

| 字段     | 说明                   | 默认值           |
| -------- | ---------------------- | ---------------- |
| duration | 时长（毫秒）           | `620`            |
| easing   | 缓动曲线               | `'easeOutQuint'` |
| stagger  | 错峰强度，0 为全部同步 | `0.35`           |
| delay    | 整体延迟（毫秒）       | `0`              |

关闭动画：`animation={false}`。

### 缓动曲线

| 名称             | 特征                 | 适用                     |
| ---------------- | -------------------- | ------------------------ |
| `linear`         | 匀速                 | 循环类动效               |
| `easeOutCubic`   | 尾部较松             | 通用                     |
| `easeOutQuint`   | 尾部更松，收得最柔和 | **默认**                 |
| `easeInOutCubic` | 两端缓、中间快       | 位置迁移                 |
| `easeOutBack`    | 约 10% 过冲回弹      | 环形、雷达等「展开」动作 |

## 设计说明

**为什么要错峰（stagger）**

所有图元同时到齐，视觉上是一次「弹起」；按序错峰，视觉上是「扫过」。后者更接近人画图、机器打印的过程，也更容易让眼睛跟上数据。

`stagger = 0.35` 的含义是：最后一个图元比第一个晚 35% 的总时长开始出发。

**为什么数据更新不重播入场**

这是旧实现最生硬的地方：用户只改了一个数字，整张图却从零长一遍，像是在否定之前的阅读。现在更新走值插值——柱子从旧高度滑到新高度，折线整体平移，读者的视线可以一直跟着同一条线。

**为什么折线是逐点生长而不是整体抬升**

折线图的语义是「一条连续的线」。整条同时抬起，看起来像被整体拎起来；逐点错峰则像一支笔从左往右画过去，符合读者建立线条的直觉。

**无障碍与容错**

- 命中 `prefers-reduced-motion: reduce` 时自动跳过动画，直接呈现终态；
- 页面处于后台标签页（`document.visibilityState === 'hidden'`）时同样直接呈现终态；
- 另有一个略长于时长的兜底定时器：浏览器出于省电等原因暂停 `requestAnimationFrame` 时（无头浏览器、窗口最小化、部分低功耗模式），强制落到终态。

最后一条不是洁癖：早期版本只依赖 rAF，在上述环境里图表会**永久停在起始帧**——所有图元贴在基线上，看起来像数据全为 0。图表的正确性优先于动效。

**一致性**

动画统一由 `requestAnimationFrame` 驱动进度，SVG 与 Canvas 两种渲染器消费同一份场景数据，因此两者的动效完全一致——Canvas 无法使用 CSS 过渡，这也是没有采用 CSS 动画的原因。

## 性能

- 每帧只做一次场景重建，没有额外的布局抖动；
- 数据量大时（> 2000 点）自动切 Canvas，绘制开销从 DOM 节点数降为一次批量调用；
- 动画期间不会触碰 React 状态树中的大对象，进度保存在 ref 里，只用一个计数器触发重渲。
