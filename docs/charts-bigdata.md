# 大数据与缩放

数据点超过几百个后，屏幕像素已经无法区分相邻点，继续逐点渲染只会拖慢滚动而不会增加信息量。这一页讲三个应对手段，以及它们各自解决什么问题。

## 三个手段

| 手段                | 解决什么                        | 代价                          |
| ------------------- | ------------------------------- | ----------------------------- |
| **LTTB 降采样**     | 点数 >> 可用像素宽度            | 极值之外的细节丢失            |
| **dataZoom 缩略轴** | 想同时看到全局与局部            | 需要用户交互                  |
| **Canvas 渲染**     | DOM 节点过多导致的布局/重绘开销 | 丢失逐图元命中与 SVG 的矢量化 |

三者是叠加关系，不是替代关系：默认配置下，采样先降到 800 点，点数仍超过 2000 图元时再切 Canvas。

## LTTB 降采样

```tsx | pure
<LineChart data={bigData} sampling={800} />   // 默认值就是 800
<LineChart data={bigData} sampling={false} />  // 关闭
```

**为什么不用「每 N 个取一个」**

等间隔抽样会把尖峰跳过——而尖峰恰恰是读者最关心的。LTTB（Largest-Triangle-Three-Buckets）把数据切成若干个桶，每桶选一个「与前后选中点构成的三角形面积最大」的点，也就是离直线最远、最能代表该段形状的点。

**多系列共用一套下标**

这是实现上最容易错的地方：如果每个系列各自采样，得到的下标集合不同，折线之间就会错位，看起来像两列数据在互相穿插。因此采样统一在 x 维度上做一次，所有系列共用。

实测：100 万点采样到 800 点约 52ms（单次，Node 环境）。采样结果会被缓存，只在数据或窗口变化时重算。

## dataZoom 缩略轴

```tsx | pure
<LineChart dataZoom />                          // 默认开启，初始窗口为全量
<LineChart dataZoom={{ height: 32 }} />
<LineChart defaultZoom={[0.4, 0.7]} dataZoom />  // 初始只看中间 30%
```

受控用法：

```tsx | pure
const [zoom, setZoom] = useState<[number, number]>([0, 1]);

<LineChart dataZoom zoom={zoom} onZoomChange={setZoom} />;
```

交互：拖左右手柄改变窗口、拖动窗口整体平移、点击轨道跳到该位置。窗口最窄 2%（再窄就只剩一两个点）。

**窗口变化会重算 y 轴**

只取局部数据后，y 轴会按窗口内的范围重新计算——否则放大到一段平缓区间时，曲线会压成一条直线，什么也看不出来。

**窗口变化不做补间动画**

点数量变了，新旧数据之间没有对应关系，硬插值会让图「从 0 长出来」。动画状态机会在形状变化时直接落到目标状态，这比强行过渡更自然。

## Canvas 渲染

```tsx | pure
<LineChart renderer="canvas" />
<LineChart renderer="svg" />      // 强制 SVG
<LineChart renderer="auto" />     // 默认：图元超过 2000 自动切 Canvas
```

Canvas 不适合交互密集的场景：它没有独立图元，hover 只能按 x 轴索引命中，无法精确到某个圆点。因此自动切换的阈值定在 2000——到这个量级，精确命中的价值已经让位于流畅度。

## 建议配置

| 数据量      | 建议                                              |
| ----------- | ------------------------------------------------- |
| < 500       | 默认配置即可，无需采样                            |
| 500 ~ 5000  | 保持 `sampling` 默认（800），关闭 dataZoom 更清爽 |
| 5000 ~ 5 万 | `dataZoom` + 默认采样，让用户自己选区间           |
| > 5 万      | 同上，并考虑预聚合（按分钟/小时汇总后再交给图表） |

最后一条值得强调：**图表不是数据库**。十万个点的原始数据交给任何图表库都不会好看，先聚合再画，往往是收益最高的一步。
